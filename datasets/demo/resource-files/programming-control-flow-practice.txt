WHY CONTROL FLOW MATTERS
------------------------
Variables store data; control flow decides what runs next. Almost every practical
program combines sequence, selection (if/else), and iteration (loops). Errors in
control flow are among the most common beginner bugs: off-by-one loops, missing
else branches, and conditions that never become false.


SECTION 1 — CONDITIONAL LOGIC
-----------------------------
Read the problem before coding. Underline inputs, outputs, and edge cases.

Example policy: grade classification (pseudocode)
  IF score >= 90 THEN label = "A"
  ELSE IF score >= 80 THEN label = "B"
  ELSE IF score >= 70 THEN label = "C"
  ELSE label = "Needs review"

Boundary cases to test: 89.9 vs 90, 0, negative input (reject), empty input.


SECTION 2 — LOOPS
-----------------
While loop: use when repetitions are unknown until a condition changes.
  WHILE user has not quit:
    read command
    process command

For loop: use when the number of iterations is known or you iterate a collection.
  FOR i FROM 1 TO 10:
    print i

Boundary cases: first iteration, last iteration, zero iterations (empty collection),
infinite loop risk when condition never updates.


SECTION 3 — TRACING AND DEBUGGING
---------------------------------
Tracing table (sample):

  line | x | y | output
  -----|---|---|-------
  init | 3 | 0 |
  while| 3 | 3 | 3
  while| 2 | 6 | 6
  while| 1 | 9 | 9
  while| 0 | 12| 12

Debugging checklist:
  1) Reproduce with the smallest input.
  2) Print or log values at branch points.
  3) Compare actual vs expected trace row by row.
  4) Check loop exit condition and update statements.


SECTION 4 — SIMPLE ALGORITHM DESIGN
-------------------------------------
Problem: count how many numbers in a list are above average.
  1) Compute sum and count; average = sum / count (guard count > 0).
  2) Second pass: increment counter when value > average.
  3) Return counter.

Deliverable quality: handle empty list without division by zero.


MINI EXERCISES (INCREASING DIFFICULTY)
--------------------------------------
Easy:
  E1) Print numbers 1..N. What breaks when N is 0? When N is negative?
  E2) Given age, print whether voting eligibility applies (use your locale rules as comment only).

Medium:
  M1) Sum digits of an integer (loop until n becomes 0).
  M2) Guess-the-number: loop until correct, count attempts.

Harder:
  H1) Print first K prime numbers (nested loops acceptable; optimize later).
  H2) Menu-driven calculator: loop until user selects quit; validate numeric input.
